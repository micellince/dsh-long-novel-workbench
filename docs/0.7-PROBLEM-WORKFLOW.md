# 找问题 → 修改：产品逻辑（定稿 v2）

> 2026-10-26 按作者口述定稿。只定义「东西是什么、从哪来、能做什么、到哪去」，不谈实现。
> 本文覆盖：问题单、修改稿、两个找问题入口、四类问题、处理粒度、采纳/继续改、批量/逐条、全局问题。
> **不覆盖**（作者明确：保持现状、不要动）：编辑器、注意力打分机制、账本机制、数据库机制、全文生成/全文改写能力。

---

## 0. 总原则

1. 工作台只产出两种东西：**问题**（正文哪里不好）和**修改稿**（能直接顶替原文的文字）。
2. 问题的唯一去处是变成稿；稿的唯一去处是**采纳进正文**或**继续改**。
3. 本次只重做「不断审阅、不断提案」这一块；编辑器、注意力打分、账本、数据库、全文生成/改写全部不动。
4. 提案这个中间对象取消。

---

## 1. 两个基本概念

### 问题
正文的毛病，四类之一：**AI 化 / 逻辑与事实 / 文风漂移·较差 / 其他**。

每条问题带：

- **类型**：四选一，互斥。
- **范围**：单章 / 跨章（明确列出章号）/ 全局（全书）。
- **严重度**：最严重 / 严重 / 一般 / 提醒。
- **位置**：章 + 段（或逐字引文）；跨章/全局问题列出涉及章。
- **说明**：一句话说清读者卡在哪。
- **修改稿**：默认必须有（能直接顶替原文）；实在给不出的，先走「共同建议」再出稿。

不同类的问题**不合并**。同一段上两条不同类的问题就是两条，各自出稿、各自采纳。

### 修改稿
可以是一段、一整章、或若干章。粒度由问题决定（见 §4）。

- 一条问题可以有 0..N 份稿（全局问题落到几章就是几份）。
- 稿有版本：继续改生成新稿，旧稿留历史、只显示最新。
- **只有稿能采纳；问题本身不能被采纳。**

---

## 2. 找问题只有两个入口

### 2.1 作者批阅
作者在正文里选中文字（或整章）→ 提一条问题。

- 类型默认「其他」，作者可改。
- 作者可以写「我的要求」让 AI 出稿；也可以自己直接改正文。
- 作者批阅与 AI 发现进**同一张问题单**，来源只做标签，不再分两套。

### 2.2 AI 审稿：两个独立档，都必须「给 TXT + 一个 AI 读完」

**铁律（作者定）：**

1. 不管是哪一档，**必须直接给 TXT**：全文 TXT 或指定章节 TXT。
2. **一个 AI 从头读到尾，不许拆子 agent、不许分章交给多个 AI 再合并。**
   - 原因：子 agent 各看单章没问题，合并后全局逻辑就散了；跨章/全局问题正是要靠一次读完才能看出来。

#### 档 A：通读档（冷读 + 去 AI 化合并）

一次读完 TXT，一次给全：

1. **注意力评分**：每章 0–100 + 一句结论；全书一个总分。
2. **问题**：AI 化 / 文风漂移·较差 / 其他，按类分开列，每条带范围、严重度、位置、修改稿。
3. **高光**：写得好的地方，**直接进账本**，不是问题。

不再有「先出一条总结、再按章拆分」。一次通读直接出结构化问题清单，**拆分动作消失**。

#### 档 B：事实与逻辑（单独一档）

必须单独一档——只有专门做这一档，才能把事实与逻辑捋清楚。分两步：

1. **自动扫库版（0 AI，保留现有能力）**：扫账本/数据库，列出人物、时间、数字、专名、设定上的可疑点。
2. **可选 AI 审这一版**：把 **TXT（全文或指定章）+ 自动扫出的可疑点** 交给**一个** AI，一次读完：判真假、找跨章连锁、给修改稿。

产物同样进同一张问题单，本档重点是「逻辑与事实」。

**全量记录（v2.1 补充）**：档位只决定「首要目标」，不是过滤器。任何一档读完全文，读到的所有问题都要按性质提交——通读审读到逻辑 / 事实矛盾要报 `logic-fact`；事实与逻辑读到成对重复段落、文风漂移也要报 `style` / `other`。丢掉等于让作者再读一遍、再烧一次 token。

#### 范围（两档通用）

- **单章**：导出该章 TXT。
- **跨章**：明确列出章号（例：第 2 章 + 第 15 章），导出这几章 TXT。
- **全局**：导出全文 TXT。

**不允许**按「每 5 章 / 每 10 章」自动分批。要分批，由作者明确指定章号。

---

## 3. 一次审稿产出三样，去处不同

| 产出 | 去哪 | 占不占待办 |
|---|---|---|
| 注意力评分（章分 + 全书总分 + 结论） | 账本/曲线（保持现有打分机制不变） | 否 |
| 问题单（四类 × 范围 × 严重度 × 位置 × 说明 × 修改稿） | 待处理 | 是 |
| 高光 | 账本 | 否 |

**评分不是问题，高光不是问题，只有问题进待办。**

---

## 4. 处理粒度标准（这次新增的核心规则）

问题严重度 → 修改稿粒度，按这个标准走：

| 情况 | 稿的粒度 | 理由 |
|---|---|---|
| 单点、局部，一段内能解决 | **段级稿**：一段换一段 | 改动最小、最好采纳 |
| 单章内问题多，或问题严重 | **整章改写稿** | 整章改写比一段段修**更省 token**，也更容易自洽 |
| 跨章连锁问题（例：第 2 章与第 15 章对不上，或同一段落在几章重复） | **涉及章各一份稿**：每章只是小改 → 段级稿（每份带 chapter + para/quote）；修几段解决不了 → 整章稿 | 按每章改动大小选粒度，不强制整章 |
| 全局问题，但只是一些分散的小毛病 | 多份段级稿 | 不需要动整章 |
| 全局问题、严重、牵动多章 | 多份整章改写稿 | 同上 |

补充规则：

- **判定人**：AI 先按这个标准给出建议粒度和稿；作者不同意，可以在「继续改」里改粒度（要求拆成段稿或整章重写）。
- **AI 的段级稿不许增删段落**（一段换一段）。
- **作者自己用编辑器可以任意增删段落**（删三段删两段都可以）——编辑器保持现状，不受这条限制。
- 整章改写稿 / 多章整章改写稿，采纳时是**整章替换**（段数可变），不按段定位，所以不会出现「改错第几段」。
- **跨章 / 全局问题允许按章给段级稿**：每份必须带 `chapter` + `para`（或该章逐字 `quote`），服务端按该章正文重新定位段号；只有「修几段解决不了」才用整章稿。

## 5. 处理动作：采纳 / 继续改 / 忽略

1. **采纳**
   - 段级稿 → 替换该段。
   - 整章稿 → 整章替换。
   - 多章稿 → 逐章采纳。
   - 一条问题下的所有稿都采纳后，问题自动「已采纳」。
2. **继续改**
   - 作者写「我的要求」→ **回到产生这条问题的那条对话**（上下文还在）→ 出新稿 → 再采纳/继续改。
   - 作者建议不是终点，只是继续改的输入。
3. **还没稿的问题**（多出现在全局/硬逻辑）
   - 先「共同建议」：AI 给处理方向，作者补判断/裁定；
   - 再按 §4 出稿（通常是整章/多章改写稿）；
   - 出稿后就可以采纳。
4. **忽略**
   - 不认同的问题（AI 误报、换设定后已不成立）点「忽略」；
   - **不删除、不催办、不进批量继续改**，但仍留在库里；
   - 随时可在「已忽略」筛选里「撤销忽略」，回到待处理。

**忽略 ≠ 删除。** 问题一直留在库里，只是不再占正常待办。

---

## 6. 批量和逐条

- **逐条处理**：一条问题 → 出稿 → 采纳/继续改。
- **批量处理**：作者勾选多条问题 → 一次生成一批修改稿（同一个对话里一起做）→ 回来后逐条采纳/继续改。
- 批量的边界 = **作者勾选的范围**，不按固定章数自动切。
- 批量只解决「一次生成多份稿」；采纳仍然按稿/按章逐份进行。

---

## 7. 状态（极简）

**问题**：待处理（有稿）/ 待处理（无稿，先共同建议）/ 已采纳。
**稿**：待采纳 / 已采纳 / 已作废（被新稿替代，或原文已变）。

- 不设驳回、合并、已随处理、失效等中间态。
- 原文被作者改过、稿对不上的，不叫失效，叫「稿作废，问题回到继续改」。
- 问题先放着不动是允许的，不强制处理。

---

## 8. 高光 / 评分 / 账本

- **高光**：冷读发现的亮点，直接进账本，不以问题形式出现，不占待办。
- **注意力评分**：保持现有打分机制与展示，只作为审稿报告结果与账本曲线，不变成问题。
- **账本、数据库**：本次一律不动。

---

## 9. 全文生成 / 全文改写

- 保持现有能力，后面只改「输出物」的叫法：产出的是**稿**，逐章采纳或继续改。
- **提案对象取消**；不再有提案页、提案审批。

---

## 10. 保持不动的部分（作者明确）

| 保持 | 说明 |
|---|---|
| 编辑器 | 阅读/编辑/批注、自由增删段落、保存逻辑 |
| 注意力打分机制 | 评分怎么来、怎么存、怎么展示 |
| 账本机制 | 人物/地点/事实/事件/伏笔/冲突/高光 |
| 数据库机制 | 数据存取、索引、同步 |
| 全文生成 / 全文改写 | 现有能力与入口 |

**唯一重做**：审阅 → 问题单 → 修改稿 → 采纳/继续改（含批量），也就是「不断审阅、不断提案」这一整块。

---

## 11. 删除 / 替换清单

| 删掉 | 原因 |
|---|---|
| 提案（对象、页面、审批） | 就是修改稿，没有独立存在的必要 |
| 冷读「先出总结再按章拆分」 | 一次通读直接出分类问题；拆分是多余动作 |
| 高光作为问题/意见 | 高光只进账本 |
| 作者问题 / AI 问题两套分栏 | 一张问题单，来源只是标签 |
| 同段合并、已随处理、失效、驳回、六状态 | 收敛成「待处理 / 已采纳」+ 稿状态 |
| 四拍 | 注意力只看评分 |
| 「注意力」当作问题类型 | 评分不是毛病 |
| 去 AI 化与冷读两个独立入口 | 合并为一次通读 |
| 子 agent 分章审阅再合并 | 改为「给 TXT、一个 AI 读完」 |
| 按每 5 章 / 10 章自动分批 | 范围只按作者指定：单章 / 跨章 / 全局 |

## 12. 一张图

```
作者批阅 ─┐
          ├─→ 同一张问题单（4 类 × 单章/跨章/全局 × 严重度 × 位置 × 说明）
AI 审稿 ──┘
  ├ 档 A 通读（冷读+去AI化）：一份 TXT，一个 AI 读完
  │    → 评分 + AI化/文风/其他问题 + 高光→账本
  └ 档 B 事实与逻辑（单独档）：
       ① 自动扫库出可疑点（0 AI）
       ② 可选 AI 审这一版：一份 TXT + 可疑点，一个 AI 读完
       → 逻辑与事实问题
                    │
                    ▼
      按粒度标准出稿：段级 / 整章改写 / 跨章各整章
                    │
                    ▼
        采纳 → 正文更新，问题关闭
          └ 继续改（我的要求）→ 原对话返工 → 新稿 → 再采纳/继续改
          └ 不想动 → 放着不动
```

## 13. 为什么之前乱（作者诊断，作为设计依据）

1. 子 agent 分章看，单章没问题，合并后全局逻辑出大问题 → 所以必须给 TXT、一个 AI 读完。
2. 冷读先出总结再拆分：多了总结、多了拆分、拆出来的东西没地址 → 直接一次出结构化问题。
3. 审阅→提案来回叠加，中间对象太多，改了几十版 → 只留「问题 + 稿 + 采纳/继续改」。
4. 严重问题逐段修，修不完也修不自洽 → 严重度直接决定粒度：严重就整章改写，跨章连锁就相关章整章重写（还更省 token）。
5. 问题类型混在一起、没有章节/全局标签 → 四类分开 + 范围标签。
