# 0.7 架构：原文优先 + 段落地址 + 数据库 + 冷读

> 本文件是 0.7 开发版（`0.7.0-dev.0`）的设计与测试说明；0.6.11 的公开说明仍以 README 为准。

## 一、四条硬原则

1. **编辑器与作者最高优先**：正文是 `.txt` 原文，编辑器只渲染原文、不拼任何代码生成的字；作者改完就是最终真相。
2. **ATTENTION IS ALL YOU NEED**：注意力 = 冷读，只回答「读者会不会继续读」，一个 0–100 分 + 地址评价；四拍不再评价正文。
3. **意见永不丢弃**：用户批注与 AI 意见同库；地址定位不了只标 `stale`，不删、不进孤儿箱。
4. **微观动作只交换地址与差量**：AI 审阅一次交付「段落地址 + 替换成文」，用户同意即替换，不再二次提案。

## 二、数据长什么样

```
<作品数据目录>/
  chapters/NNNN.txt           ← 正文成品：首行回目标题 + 正文（可直接发人）
  chapters/NNNN.meta.json     ← 章节元数据（标题索引/状态/摘要/地点/时间/人物/hash/字数）
  chapters/NNNN.index.json    ← 段落索引：pid / hash / 偏移 / 段首预览（本地生成）
  novel.db                    ← SQLite：章节 / 段落 / 实体 / 别名 / 提及 / 事实 / 事件 / 伏笔 / 冲突 / 高光 / 意见
  reviews.json                ← 过渡期兼容：旧审阅仍写这里，并双写意见库
  attention.json              ← 冷读：score / verdict / points / scoredAt / scoredHash
  proposals.json runs.json    ← 旧链路保留（0.7 的 AI 审阅不再走提案）
  账本 JSON（facts/characters/…）← 仍是账本页当前展示源；DB 为索引与增量同步
  .backups/                   ← 章节历史；.backups/review-history/ ← 审阅写入前备份
```

- `contentHash` / 段落 `bodyHash`：**只算正文、不含标题行**。改标题不让注意力分、提案校验失效。
- 段落地址：`pid = c<章>p<段号>`，hash 是段落文本 sha1 前 12 位；`para` 从 0 开始（不含标题）。

## 三、一次定点审阅的完整流程（省钱链路）

1. 作者在正文选中文字（或点「整章意见」）→ 提交批注 → **toast 成功反馈**（失败保留输入）。
2. 派单给对应角色子 agent：`logic→事实逻辑设计师`、`ai-style→审核 AI 化的 AI`、`attention→冷读审稿人`、`reader→文笔文风优化师`。
3. 子 agent 只拿自己需要的材料（段落切片 / 可疑点 / 整章纯文本），返回 `{para, quote, issue, after}`。
4. 主对话（编辑）只验收：地址合法、after 是整段成文、字数/条数不超限。
5. 作者在「意见库」采纳 → 服务端按段替换并走唯一 `saveChapter`（备份 + 闸门 + 重建索引 + 账本增量同步 + 意见重定位）。
6. 冷读的 `highlight` 意见被采纳 → 写入账本高光表。

## 四、省钱点

| 动作 | 0.6 | 0.7 |
|---|---|---|
| 定点修一条 | 审阅读整章 + 提案再读整章 + 输出 before/after | 只给相关段落 + 只输出 after（约省 80%） |
| 冷读 | 四拍长文分析 2k+ 输出 | score + 若干地址评价（comment ≤80 字） |
| 账本日常同步 | 软件提示、人工/AI 核对 | 保存正文本地增量同步（0 AI） |
| 全书账本 | 常整本读 | 首次建账一次 + 之后增量 |

## 五、角色（7 个）

| 角色 | 何时 | 只给 | 输出上限 |
|---|---|---|---|
| 编辑 | 主对话验收 | 子 agent 结果 | 不产生成文 |
| 出版人 | 全文写作/改写前 | 全书简报 | ≤300 字定调 |
| 作者 | 写/改全文 | 定调 + 大纲 + 账本摘要 | 按章 |
| 文笔文风优化师 | 文风/语感（可按段或全文范围） | 段落切片 + 预设摘要 | 每条只改一段 |
| 事实逻辑设计师 | 事实/连续性 | 可疑点 + 相关事实 | 只判可疑点 |
| 冷读审稿人 | 冷读 | 整章纯文本 | score + points |
| 审核 AI 化的 AI | AI 味 | 被标记段落 | 每条只改一段 |

## 六、插件升级

- `apply()` 装配期全程 try/catch，不拖垮 DSH；`diagnostics` 看启动错误。
- 设置页「🔄 插件更新」：查 npm 最新版；npm 安装形态可一键更新/回退；**git 源码副本拒绝自动覆盖**（提示 `git pull`）。
- SQLite 自检失败自动降级 JSON，并在顶部横幅提示。

## 七、测试清单（作者手测）

1. 重载插件 + 刷新页面。
2. 设置页：数据存储 = SQLite；账本数据库计数；分工 7 角色；插件更新卡。
3. 正文页：只显示原文；首行标题可选中；「📄 整章意见」可提交并有成功提示。
4. 意见库页：按段分组、合并、采纳（含 after 替换）、驳回、stale 显示。
5. 冷读：发起工作单 → AI 提交 → 右栏显示分数与地址评价；采纳亮点 → 高光入账。
6. 保存一章：`chapters/NNNN.index.json` 与 `novel.db` 更新；账本提及计数变化。
7. 标题迁移：设置页「📝 标题进正文」先预演 → 应用（逐章备份）。
8. 删除一章：意见变 stale（不删），索引/提及清理。
