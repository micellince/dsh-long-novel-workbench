# v0.4.0 开发契约（内部文档）

> **状态：已实现并验收（2026-10-22）。** 本文保留作 v0.4 的数据/API/前端/测试口径参考；
> 后续改接口时请同步更新本文件，或在新版本里另起契约。

目标：在 v0.3.1 基础上完成 P1/P2/P3 剩余功能，版本号升到 **0.4.0**。
本文件是三条并行工作线的唯一接口约定。**契约没写到的行为，以现有代码为准；要改契约先找 Lead。**

## 0. 通用约束

- Node `^22.19.0 || >=24.0.0`，ESM（`"type": "module"`），**不新增任何 npm 依赖**。
- 不引入构建步骤。客户端仍是 `window.__ModuleLoader__.load` + `React.createElement`。
- 用户数据是普通 Markdown/JSON，落在 `STORY_DESK_ROOT`（默认 `~/StoryDesk`）。
- 向后兼容：老数据（没有新字段）必须照常工作。
- 注释用中文，风格与现有代码一致（无分号、2 空格缩进、单引号）。
- **任何人不要执行 `git commit` / `git push` / `npm publish`**，Lead 统一提交。
- 所有路径只允许落在 `STORY_DESK_ROOT` 与测试临时目录内（导入功能除外，它读用户显式给出的目录，只读）。

## 2. 数据模型变更

### 2.1 事实账本：时间维度

`facts` 条目新增两个**可选**数字字段：

- `validFrom`：生效起始章（含）
- `validTo`：生效结束章（含）

缺省语义：`validFrom` 缺省 = 从第 1 章起；`validTo` 缺省 = 一直有效（`Infinity`）。
边界：同一 `subject + attribute` 下，只有两个取值的**生效区间重叠**且 `value` 不同才报 `fact-conflict`。
区间 [a1,a2] 与 [b1,b2] 重叠判定：`a1 <= b2 && b1 <= a2`。
其他检查（事实写到未来章节等）不变。

### 2.2 章节版本

- 每次 `saveChapter` 覆盖已有章节且内容确实变化时，先把**旧文件原文**备份到
  `projects/<id>/.backups/<chapterId>-<ISO时间戳去冒号>.md`，再写新文件。
- 每个章节最多保留最近 **100** 个备份，超出删除最旧的。
- 内容没变（新序列化文本 === 旧文件文本）不产生备份。
- `acceptProposal` 原有的 `backupChapterFile` 行为保留，但统一走同一套备份函数。

### 2.3 当前预设

`project` 新增可选字段 `activePresetId`。`updateProject` 的允许字段增加 `activePresetId`。
`applyPreset` 除了写 targetChapters/targetWords，还要写 `activePresetId = presetId`。

### 2.4 预设多卷（可选字段）

预设可带可选数字字段 `chapterFrom` / `chapterTo`。对齐计算规则：

1. 若 `project.activePresetId` 命中某预设 → 用它；
2. 否则若有预设带 `chapterFrom` → 视为分卷方案：`plannedChapters = max(chapterTo)`，
   `totalWords = Σ(该预设 totalWords)`，`chapterWords = round(totalWords/plannedChapters)`；
3. 否则用第一个预设（保持旧行为）。

## 3. 后端 API（lib 导出 + HTTP op）

### 3.1 章节历史

```js
listChapterHistory(root, projectId, chapterId)
// -> [{ file, savedAt, bytes }]  按 savedAt 倒序，最多 100 条

readChapterHistoryVersion(root, projectId, chapterId, file)
// -> { file, savedAt, content }

restoreChapterVersion(root, projectId, chapterId, file)
// 先把当前正文备份，再把指定备份写回 chapters/<id>.md
// -> { chapter, backup }   backup 是恢复前快照的路径
```

HTTP op：`chapter.history`、`chapter.version`、`chapter.restore`
（body：`{projectId, chapterId, file?}`）。

### 3.2 批量提案 / 审稿

```js
batchAcceptProposals(root, projectId, ids)   // -> { accepted: [{id, applied}], failed: [{id, error}] }
batchRejectProposals(root, projectId, ids)   // -> { rejected: [id], failed: [{id, error}] }
batchUpdateReviews(root, projectId, ids, patch) // -> { updated: number, missing: [id] }
```

- 单条失败不影响其他条；`failed` 里放 `{id, error}`。
- `batchUpdateReviews` 只允许改 `status`（`open|fixed|wontfix`），其他字段忽略。
- HTTP op：`proposal.batchAccept`、`proposal.batchReject`、`review.batchUpdate`
  （body：`{projectId, ids, status?}`；旧的单条 op 保留）。

### 3.3 导入 Markdown

```js
scanImport(root, dirPath)
// 递归扫描目录（最大深度 5，跳过隐藏目录、node_modules、.git）
// -> { path, files: [{ file, relPath, words }], chapters: [{ index, title, words, source }], totalWords }

runImport(root, { path, projectName, genre?, mode? })
// mode: 'new'（默认，新建作品）| 'append'（追加到 projectId 指定作品）
// 切章规则：优先按 Markdown 一级/二级标题（# / ##）切；没有标题则一个文件一章，
// 标题取文件名；忽略 frontmatter；空章节跳过。
// -> { projectId, projectName, chapters: [{id, title, words}], skipped: [] }
```

- HTTP op：`import.scan`、`import.run`（body 同上）。
- 导入不能写坏已有作品；`append` 模式下章节 id 从现有最大章号续号。

### 3.4 导出

```js
exportBook(root, projectId, format)
// format: 'md' | 'epub' | 'docx'
// md   -> { filename, mime: 'text/markdown', markdown }
// epub -> { filename: '<书名>.epub', mime: 'application/epub+zip', base64 }
// docx -> { filename: '<书名>.docx', mime: 'application/vnd.openxmlformats-officedocument.wordprocessingml.document', base64 }
```

- HTTP op 仍是 `export`，新增可选 `format`（默认 `md`，保持旧返回结构）。
- 兜底：`export` 返回里的 `markdown` 字段只在 md 时存在；epub/docx 时用 `base64`。

### 3.5 打包（无依赖）

```js
// lib/zip.js
createZip(entries) // entries: [{ name, data: string|Buffer, store?: boolean }] -> Buffer
```

实现 ZIP（deflate 用 `node:zlib` 的 `deflateRawSync`；`store: true` 不压缩，EPUB 的 `mimetype` 必须 store 且是第一个条目）。
CRC32 自己实现。文件名 UTF-8。

```js
// lib/exporters.js
buildEpub(bundle) // -> Buffer
buildDocx(bundle) // -> Buffer
```

EPUB 至少包含：`mimetype`（store）、`META-INF/container.xml`、`OEBPS/content.opf`、
`OEBPS/nav.xhtml`、每章 `OEBPS/chap-<id>.xhtml`。EPUB 3，`dc:title`/`dc:language`/`dc:identifier` 必填。
DOCX 至少包含：`[Content_Types].xml`、`_rels/.rels`、`word/document.xml`、`word/styles.xml`、
`word/_rels/document.xml.rels`。正文按段落拆 `w:p`，章节标题用 `Heading1` 样式。

### 3.6 事实时间维度

- `lib/checks.js` 冲突逻辑按 2.1 改。
- 不新增 op：事实仍走 `entity.upsert`。

## 4. 客户端（client.js）

### 4.1 人物关系图

- 人物页增加「列表 / 关系图」切换（默认列表）。
- `relationships` 支持 `名字(关系)`、`名字（关系）`、`名字:关系`、`名字：关系`；目标不在人物库时画虚线幽灵节点。
- SVG 力导向布局（确定性初始化 + 约 80 次迭代），节点按 role 着色，边带关系文字。
- 节点可拖拽；悬停高亮相邻节点/边；点击节点打开该人物编辑卡。
- 数据为空时给空状态提示，不报错。

### 4.2 时间线泳道图

- 时间线页增加「列表 / 泳道」切换。
- 泳道：优先按项目卷（若数据里有 `volume` 字段），否则按每 20 章一条泳道；横轴 = 章号。
- 事件卡片按 `importance` 着色，位置由 `chapter` 决定；点击打开事件编辑。
- 伏笔 `setupChapter → payoffChapter` 用曲线连接（未回收实线、已回收虚线/灰色），跨泳道也画。
- 顶部有缩放滑块（0.5x–3x）；空数据给空状态。

### 4.3 自动保存 + 版本 diff

- 章节编辑器：内容改动后 5 秒防抖自动保存（状态仍按草稿），显示「保存中… / 已自动保存 HH:mm」。
- 关闭编辑器时若还有未保存改动，提示确认。
- 章节编辑器增加「历史版本」按钮：列出 `chapter.history`，点某版本看 diff（复用 `diffLines`），可「恢复此版本」。
- 手动保存仍保留原有行为（按钮 + 状态/摘要/人物等字段）。

### 4.4 批量审稿 / 采纳

- 提案页：待采纳提案加复选框、全选、按类型筛选；支持「批量采纳」「批量驳回」。
- 审稿页：复选框 + 全选 + 「标记已修 / 忽略」批量操作；支持按严重度筛选。
- 失败条目要提示，不要静默失败。

### 4.5 事实时间维度 UI

- 事实表单增加「生效章」「失效章」两个可选数字字段。
- 事实列表列显示区间（如 `第3章起` / `第3–10章` / `全程`），没有值时不显示。
- 编辑旧数据不能丢字段。

### 4.6 导入 / 导出 UI

- 作品库页增加「导入 Markdown」：输入本机目录路径 → 扫描预览（文件数/章节数/总字数/前 20 章标题）→ 填作品名 → 导入 → 打开新作品。
- 工作台顶栏（或作品页）增加「导出」：Markdown / EPUB / DOCX 三个选项，前端用返回的 base64 触发下载。
- 所有新 op 失败时用 `window.alert` 提示可读错误。

### 4.7 多预设

- 预设页每套预设加「设为当前」；当前预设显示标记。
- 对齐页显示当前预设名；后端已按 2.4 计算。

## 5. 测试（verifier）

`test/` + `node --test`，零依赖（`node:test` + `node:assert/strict`）。

必须覆盖：

1. `checks`：事实区间冲突（不重叠不报、重叠报、缺省全程）、伏笔超期、未建卡人物。
2. `store`：创建作品/章节、`saveChapter` 自动备份、历史列表/读取/恢复、内容不变不备份。
3. 提案：单条/批量采纳与驳回、失败隔离、章节采纳前备份、修订回链（现有行为回归）。
4. `checks.computeAlignment`：activePresetId、多卷预设、缺省回退。
5. `import`：临时目录扫描、标题切章、append 续号。
6. `export`：ZIP 结构（mimetype 首条且未压缩）、EPUB 必需文件、DOCX `word/document.xml`、md 输出。
7. 所有测试用 `mkdtemp` 临时根，不碰 `~/StoryDesk`。

`package.json` 只加 `"scripts": { "test": "node --test test/" }`。
