# v0.7.1 · 长篇中文小说工作台

**发布日期**：2026-10-26
**npm**：`dsh-long-novel-workbench@0.7.1`
**GitHub**：<https://github.com/micellince/dsh-long-novel-workbench/releases/tag/v0.7.1>

这是 0.7 线的第一次公开发布（`0.7.0-dev.0` 是未对外发布的开发线，本版统一以 `0.7.1` 发布）。

0.6.11 把界面收成了「读 → 批注 → 审 → 改」；0.7.1 继续把其中最容易乱的一段——**审**和**改**——重新做成两个朴素的对象：

- **问题**：正文哪里不好；
- **修改稿**：能直接顶替原文的文字。

问题进一张统一的问题单，修改稿采纳就替换正文，不满意就让 AI 继续改，误报可以忽略。**不再经过「审阅意见 → 提案 → 批准」这几层**。

---

## 一、这一版解决什么

写长篇时，AI 给的意见经常有三类麻烦：

1. **问题散**：一会儿是审阅条目，一会儿是冷读总结，一会儿要按章拆，最后没人说得清「这本书现在有哪些问题」；
2. **改法绕**：意见要先生成提案、提案再批准，改法在几个对象之间来回搬；问题本身还不能直接被采纳；
3. **改错位置**：意见只有「一段原文」，正文一改地址就对不上；拆出来的意见甚至没有地址。

0.7.1 的答案是收口：

- 只有**两种东西**：问题、修改稿；
- 问题必须带**范围**（单章 / 跨章 / 全局）和**位置**（章 + 段，或逐字引文；跨章 / 全局列出涉及章）；
- 修改稿默认必须有，而且必须是能直接顶替原文的成文文字；
- 只有稿能采纳；问题本身不能被采纳；
- 采纳就是替换（段级稿一段换一段，整章稿整章替换），不进第二层审批；
- 不满意就**继续改**——回到产生这条问题的那条对话，出新稿，再采纳；不认同就**忽略**，不删除、可撤销。

---

## 二、两个对象：问题 与 修改稿

### 问题

四类之一，互斥：**AI 化 / 逻辑与事实 / 文风漂移·较差 / 其他**。

每条问题带：类型、范围（单章 / 跨章 / 全局）、严重度（最严重 / 严重 / 一般 / 提醒）、位置（章 + 段或逐字引文；跨章 / 全局列出涉及章）、一句话说明、修改稿。

- 作者批注与 AI 发现进**同一张问题单**，来源只做标签（作者 / AI / 本地扫库），不再分两套。
- 同一段上两条不同类的问题就是两条，各自出稿、各自采纳，不合并。

### 修改稿

可以是一段、一整章，或若干章各一份。粒度由问题决定（见第四节）。

- 一条问题可以有 0 到多份稿：跨章 / 全局问题落到几章就是几份。
- 稿有版本：继续改会生成新稿，旧稿留历史，只显示最新。
- 稿只管「顶替原文」：段级稿不增删段落、不许空行；整章稿是整章替换（段数可以变），所以不会出现「改错第几段」。

## 三、找问题只有两个入口

### 3.1 作者批阅

在正文里选中文字（或整章）→ 提一条问题。

- 类型默认「其他」，你可以改；
- 可以写「我的要求」让 AI 出稿，也可以自己直接改正文（编辑器保持原样）；
- 批注与 AI 发现的问题进同一张问题单。

### 3.2 AI 审稿：两个独立档

**铁律：不管哪一档，都必须直接给 TXT，并且由一个 AI 从头读到尾。** 不拆子 agent、不分章交给多个 AI 再合并——跨章和全局问题，只有一次读完才看得出来。

#### 档 A：通读审（冷读 + 去 AI 化合并）

一次读完 TXT，一次给全：

1. **注意力评分**：每章 0–100 分 + 一句结论，另给全书一个总分；
2. **问题**：AI 化 / 文风漂移·较差 / 其他，按类分开列，每条带范围、严重度、位置、修改稿；
3. **高光**：写得好的地方，直接进账本，不是问题、不占待办。

不再有「先出一条冷读总结、再按章拆分」——一次通读直接出结构化问题清单，**拆分这个动作消失**。

#### 档 B：事实与逻辑（单独一档）

必须单独一档。分两步：

1. **自动扫库（0 AI，保留现有能力）**：扫账本与数据库，列出人物、时间、数字、专名、设定上的可疑点，自动存成一条「事实扫库」记录；
2. **可选：让 AI 审这一版**：把 TXT（全文或指定章）+ 自动扫出的可疑点交给一个 AI，一次读完——判真假、找跨章连锁、给修改稿。

产物同样进那张问题单，本档重点是「逻辑与事实」。

**全量记录**：两档都只决定「首要目标」，不是过滤器。既然一个 AI 已经把全文读完，读到的所有问题都要按性质提交——通读审读到逻辑 / 事实矛盾也要报「逻辑与事实」；事实与逻辑读到成对重复段落、文风漂移也要按「文风漂移」/「其他」报。丢掉只会让你为同一个问题再读一遍、再烧一次 token。

#### 范围（两档通用）

- **单章**：导出该章 TXT；
- **跨章**：明确列出章号（例：第 2 章 + 第 15 章），导出这几章 TXT；
- **全局**：导出全文 TXT。

**不按「每 5 章 / 每 10 章」自动分批。** 要分批，由你指定章号。

## 四、处理：粒度、采纳、继续改、忽略、批量

### 4.1 稿的粒度（AI 先按这个定，你可以要求改）

| 情况 | 修改稿粒度 |
| --- | --- |
| 单点、局部，一段内能解决 | **段级稿**：一段换一段 |
| 单章内问题多，或问题严重 | **整章改写稿** |
| 跨章连锁问题（第 2 章与第 15 章对不上等） | **涉及章各一份**：每章只是小改 → 段级稿（每份带 `chapter` + `para`/`quote`）；修几段解决不了 → 整章改写稿 |
| 全局问题，但只是分散小毛病 | 多份段级稿 |
| 全局问题、严重、牵动多章 | 多份整章改写稿 |

整章改写往往比一段段修更省 token、也更容易自洽；但跨章 / 全局问题不必动辄整章重写，按每章改动大小选粒度即可。AI 先给建议粒度；不同意就在「继续改」里要求拆成段稿或整章重写。

### 4.2 采纳

- 段级稿 → 替换该段；整章稿 → 整章替换；多章稿 → 逐章采纳；
- 一条问题下的所有稿都采纳后，问题自动「已采纳」，卡片上会标出写入位置：**「已采纳并写入正文：第 N 章第 M 段」**（整章稿显示「第 N 章整章替换」）。

### 4.3 继续改

写「我的要求」→ 回到产生这条问题的那条对话（上下文还在）→ 出新稿 → 再采纳 / 继续改。

上一版稿进「历史稿」留底，不会自动删除；需要时可以点开，也能「恢复为待采纳」。原文被改过、稿对不上的，问题标「原文已变」，稿保留，点「继续改」按新原文重出。

### 4.4 忽略

AI 误报、或换了设定后已经不成立的问题，点「忽略」：**不删除、不催办、不进批量继续改**；仍留在库里，随时可在「已忽略」筛选里「撤销忽略」，回到待处理。

**忽略 ≠ 删除。** 问题一直保留，只是不再占正常待办。

### 4.5 批量

勾选多条问题 → 一次生成一批修改稿（同一个对话里一起做）→ 回来后逐条采纳 / 继续改。

批量的边界 = **你勾选的范围**，不按固定章数自动切。

## 五、去掉了什么（对照旧概念）

| 去掉 | 原因 |
| --- | --- |
| 提案参与审阅 / 改稿（提案页、提案审批） | 它就是修改稿，没有独立存在的必要；**提案仅保留给账本修订与全文动作** |
| 冷读「先出总结再按章拆分」 | 一次通读直接出分类问题；拆分是多余动作 |
| 高光作为问题 / 意见 | 高光只进账本 |
| 作者问题 / AI 问题两套分栏 | 一张问题单，来源只是标签 |
| 状态里的驳回 / 合并 / 已随处理 / 失效 | 收敛成「待处理 / 已采纳 / 原文已变 / 已忽略」+ 稿状态（待采纳 / 已采纳 / 已作废） |
| 四拍（钩子 / 张力 / 回报 / 章末牵引） | 注意力只看通读审的评分 |
| 「注意力」作为问题类型 | 评分不是毛病 |
| 去 AI 化与冷读两个独立入口 | 合并为一次通读审 |
| 子 agent 分章审阅再合并 | 改为「给 TXT、一个 AI 读完」 |
| 按每 5 章 / 10 章自动分批 | 范围只按你指定：单章 / 跨章 / 全局 |

## 六、保持不变的

- **编辑器**：阅读 / 编辑 / 批注三种模式、自由增删段落、自动保存与历史版本；
- **注意力打分机制**：怎么打分、怎么存、怎么在曲线里展示（通读审给出的评分仍写回注意力曲线）；
- **账本**：人物 / 地点 / 事实 / 事件 / 伏笔 / 冲突 / 高光；
- **数据库与同步**：`novel.db`、段落索引、账本增量同步；
- **全文生成 / 全文改写**：现有入口与能力不变（产物由你逐章采纳；账本相关改动仍走提案）；
- **导出、世界地图、写作预设、开新书向导**。
- **旧意见数据不迁移**：旧审阅 / 冷读 / 提案记录保留在数据里，但不进入新的问题单。

## 七、修复

这一版发布前修掉了几个会直接影响使用的问题：

- **时间显示本地化**：问题页、审稿记录的时间改为按本机时区显示（之前会显示成 UTC，差几个小时）。
- **老库升级误报「不支持 SQLite」**：修复旧作品库升级时的迁移顺序问题，旧库首次打开不再被误判为「当前环境不支持 SQLite」。
- **采纳时误判「原文已变」不再丢稿**：段落只是挪位 / 引文还能对上会自动跟随；真的对不上时，只把问题标「原文已变」，**修改稿保留不删**，可在「历史稿」里「恢复为待采纳」，也可以直接「继续改」重新出稿。
- **新增「忽略」**：AI 误报、或换设定后已不成立的问题可以忽略——不删除、不催办、不进批量继续改，可在「已忽略」筛选里撤销。

## 八、升级与数据

### 8.1 从 0.6.11 升级

0.7 的数据形态变了：

- 0.6.11：作品在 `~/StoryDesk/projects/<id>/`；
- 0.7.1：插件索引在 `~/.dsh/data/dsh-long-novel-workbench/`，**每本书的数据放在它自己的 DSH 工作区**（`~/Documents/deepseek-harness/default-workspace/<书名>/`），正文、账本与问题都在同一目录，另有 `novel.db`（SQLite）。

**0.7.1 不会自动迁移 0.6.11 的作品。** 需要时运行迁移脚本（默认只打印计划）：

```sh
node scripts/migrate-book-0.7.mjs --project <作品id>
# 确认无误后写盘（旧作品目录原样保留）
node scripts/migrate-book-0.7.mjs --project <作品id> --apply
```

迁移后旧意见 / 提案记录保留在数据里，但**不再进入新的问题单**；问题单从 0.7.1 开始按新模型记录。

> 升级前建议先备份 `~/StoryDesk` 与各作品工作区（含 `novel.db*`）。数据是纯文本 + SQLite，备份就是复制目录。

### 8.2 安装 / 升级

```sh
# 从 npm 安装（推荐）
dsh plugin --profile <你的 profile> add dsh-long-novel-workbench@0.7.1
```

也可以在 DSH 的插件管理里把 `dsh-long-novel-workbench` 升到 `0.7.1`，然后**重载插件 + 刷新页面**。装好后侧栏底部有「📖 小说工作台」入口。

## 九、已知限制

- **不自动迁移** 0.6.11 及更早的作品数据；0.5.x 的旧 `.md` 章节仍可读、原地写回。
- 旧版（0.6 / 0.7 开发线）的审阅 / 冷读 / 提案历史保留在数据里，但不再进入新的问题单，也不参与新的找问题流程。
- 审稿范围只有单章 / 跨章 / 全局三种，**不做自动分批**：超长全书一次通读时，请按需要自行指定章节范围。
- 问题单从本版开始建立；升级后第一次进入问题页是空的，需要跑一次「通读审」或「事实与逻辑」。
- 本版按项目当前规则**未运行自动化测试**，发布验收以作者手测为准（既有 `test/` 仍是 0.6 行为断言，未随 0.7 更新）。
