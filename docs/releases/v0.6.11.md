# v0.6.11 · 长篇中文小说工作台

**发布日期**：2026-10-26
**npm**：`dsh-long-novel-workbench@0.6.11`
**GitHub**：<https://github.com/micellince/dsh-long-novel-workbench/releases/tag/v0.6.11>

这是 0.5.1（2026-10-22）之后的第一次发布，也是整个插件的一次重写。

0.5 那套「19 页签流水线」不再保留：新版本只围绕一件事组织界面——**正文页**，以及写作真正在发生的那个循环：**读 → 批注 → 审 → 改**。打开就是稿子，人可以随时插进去；AI 负责写和审，改不改由你逐条批准。

> `0.6.0` → `0.6.11` 是重写期间的内部迭代版本号，对外统一以 `0.6.11` 发布，所以这次会一次拿到全部变化。

---

## 一、这一版是什么

0.5 的问题是「功能都在，但入口太多」：整本书生成、扩写、审阅、账本各占一堆页签和按钮，作者写一章要点开很多面板，AI 的动作也散在各个角落。

0.6 反过来做：

- **正文页是第一页**。连续阅读全本、页内直接改、选中文字加批注，都在同一页里完成；
- **AI 只出提案**。它写、它审，但不直接改你的稿子；改法是逐段「原文 / 改为」，你批准了才落盘；
- **审阅分四路，同权**。逻辑与事实、注意力、去 AI 味、读者批注，各自是一条独立意见流，不互相盖掉；
- **一条主线管到底**。从开新书、写正文、审阅、提案，到写完之后的账本补齐与导出，都落在同一套数据上。

## 二、亮点

### 1. 打开就是正文

工作台默认落在正文页：左边是目录（可以新建、删除章节），中间是连续滚动的全文，右边是本章信息与动作。`j` / `k` 翻章，`/` 可以搜全文并精确跳到命中的那一段，阅读位置会自动记住。

阅读、编辑、审阅三种模式共用同一篇正文：阅读是纯读，编辑是页内直接改（纯文本，停止输入两秒自动保存，也可以 `⌘/Ctrl+S` 立即保存，保存带指纹冲突检查），审阅是选中文字加批注。改稿不用在页面之间来回跳。

### 2. 沉浸模式与仿纸正文底

想认真读一章时，点「⛶ 沉浸」：顶栏、导航、目录、右栏全部收起，正文区只剩「阅读 / 编辑 / 审阅」三颗按钮，铺满整个视口。`Esc` 先退出沉浸，不会顺手把工作台关掉。

阅读区和编辑器换成同一张暖纸底——固定的纸色与墨色，不随宿主明暗主题反转；编辑器不再用等宽字体，和阅读共用字号与行距，改稿时看到的就是成稿的样子。顶栏左侧有字号控件（13–28px），宽屏窄屏都一致，用的只是页面字号，不加载任何网络字体。

### 3. 三种模式共用一个阅读位置

改稿最烦的是「切到编辑 → 从头找刚才那段 → 切回阅读又回到书首」。

这一版按「章 + 段」记住位置：从阅读或审阅切到编辑，本章打开、光标正好落在你刚读到的那一段；从编辑切回，按光标所在的段落把正文滚回原处。滚动停 300ms 就把位置记进本机浏览器，重开页面直接回到同一段；进出沉浸模式也按当前段重新落位。精度是段落级（段首对齐），只存在浏览器里，不写回作品文件。

### 4. 四路审阅，范围由你定

审阅页顶部四张入口卡：**AI 味审阅 / 事实逻辑审阅 / 注意力审阅 / 四路一起审**。点开先逐章勾选范围（默认整本书，也可以一键选「全书 / 未审过的 / 有意见的 / 清空」），再填一句「这次重点」，生成工作单发给你自己的 AI 对话。

四种意见同权：逻辑与事实、注意力、去 AI 味、读者批注。审阅只产出条目，不碰正文；每条都要引用正文原文（少于四个字、或同一句出现多次无法定位，会直接报错而不是悄悄改错位置）。收件箱分「待处理 / 已进提案 / 已处理」，可以批量标记已处理、忽略，也可以重新打开。

### 5. 提案批次：AI 只提，改不改你说了算

审阅条目勾选后，AI 会按意见把该段改写成成文正文，产出「原文 / 改为」的段落补丁——注意是**成文正文**，不是「建议改成……」。此外还支持整章重写、账本修订、跨章的全书修改三种提案。

提案页可以逐条批准 / 驳回，也可以全选后批量处理（驳回原因会写到每一条）；「改为」可以直接编辑，改完再批准；每条补丁都会挂回它对应的审阅，采纳后那条审阅自动标记为已修复。

### 6. 全文动作：从头写 / 扩写 / 改写

把需要成规模动笔的事收成一个「全文动作」：从头写新章、扩写已有正文、改写（再分文风 / 逻辑与事实 / 结构与节奏），范围可选全书、单章或区间。页面上有阶段进度，以及 token 与费用预算。

点「开工（发工作单）」才会真正开始，AI 按阶段推进、回来更新进度。只有「从头写」会把新章直接落盘（仍要过闸门），扩写和改写的产物一律只进提案。

### 7. 写完之后，把账本补上

正文写完了，账本却常常还停在写作中途——时间线缺后半本、人物卡没更新、事件是空的。

账本页的「📚 全书同步」把正文按批切开（每批 4 / 6 / 8 / 10 章，默认 6），每批生成一份工作单让 AI 读正文补账本；进度存在作品里，可以重新制定计划（章号范围相同的已完成批会保留进度），也可以清除计划；计划建好之后新写的章会提示「未覆盖」。AI 只能提账本修订提案，改动还是你逐条批准。

日常改正文时也一样：动到账本里的人名、地名、事实数字，顶部会提醒「第 N 章正文改到了账本里的名字/数字」，可以「让 AI 核对」或者「已核对，忽略」。这条提醒对 AI 写出来的正文同样生效。

### 8. 世界观与资料库

账本页容纳 9 个页签：**事实库 / 人物卡 / 时间线 / 地点 / 世界地图 / 高光 / 冲突 / 伏笔 / 大纲**。

- 人物卡按角色分组，点开看目标、缺陷、弧光、关系与首现章，可直接编辑；
- 时间线按故事时间排（年 / 月分组），事件带章号，点一下跳正文；
- **世界地图**按你自己的地点坐标直绘，不拉伸、不挪点、不做疏密变形：长安在洛阳西边，就画在西边。上面有分区底纹、驿道路线、水线山形和地名避让，四个图层可以单独开关；全屏后能滚轮缩放、拖动、重置、点地点看详情。想换观感，改作品里的画风设置即可（水墨绢本 / 赭石古卷 / 青绿山河 / 羊皮纸 / 冷灰史诗 / 暗红纪事）；
- 0.5.x 的旧账本数据可以直接读得到。

### 9. 开新书向导

总览页或空库页点「＋ 开新书」：只填书名（同时作为工作区名）→ 选一套写作预设（或让 AI 定）→ 写一段想法。之后插件会自动建好作品、给这本书建一个独立的工作区，并在里面新开一个对话，收到「设定 / 世界 / 地点 / 人物 / 全书大纲 / 伏笔」的工作单；AI 以提案提交，你批准后才进账本。

选「自定义（让 AI 定）」时，AI 会先出一份类型、篇幅、结构、风格加注意力总设计的方案，批准后自动成为这本书的当前预设。设置页另有 5 套内置预设（标准长篇 / 冷峻悬疑 / 家国武侠 / 文学现实 / 自定义模板），可以新建、编辑、应用或复制模板，换预设不影响正文。

### 10. 注意力一号原则与冷读打分

这一版的创作第一原则是 **ATTENTION IS ALL YOU NEED**：先想清楚读者为什么还想往下读，再动笔。

- 顶栏下常驻原则条（所有页签可见），总览页置顶显示平均注意力、最低三章、未测章数；
- 所有写 / 改工作单第一行就是「先交本章注意力设计（钩子 / 张力 / 回报 / 章末牵引四拍 + 设计分）再动笔」，并附最近 6 章曲线、疲劳预警、目标分和强制补强要求；全文动作的第一个阶段固定是「先定注意力设计」；
- 没有设计就写 / 改正文会被拒绝或收到提醒；
- 右栏可以人工校准本章四拍实测分，改动会记进历史。

**冷读打分**是另一种视角：一个独立、零上下文的会话，只拿到章节路径和你写的「打分说明」，像第一次读到的读者那样按四拍打分、写弃读点与下一章意愿，结果写回注意力曲线。审阅页和正文页都有入口；复测不透露旧分，作者填的说明会原样进工作单。

### 11. 导出与交付

顶栏「⬇ 导出」或设置页「📤 导出正文」，可以把全本导成 **TXT / Markdown / EPUB 3 / DOCX**，可选附章节提要。零第三方依赖，导出时会洗掉写作期残留的 Markdown 标记（`※` 在 TXT 里保留，在 Markdown 里转成 `***`），交稿前不用再手洗一遍。

### 12. 数据安全：单一写入闸门

所有正文写入——手动保存、提案采纳、AI 写章、全文动作——都走同一个入口：规范化 → 保真检查（专名、数字、对白、章末钩子）→ 残留扫描 → 去 AI 味 → 落盘。不过闸就返回「需要修」且不落盘，不会留下半截稿。闸门也会保留章节的标题、状态、摘要，AI 写的新章标题不会丢。

## 四、不兼容与数据兼容

**0.6 与 0.5 不能同时启用。** 两者注册了同名路由 `/novel-desk/api` 和同名工具（`novel_desk_propose`、`novel_desk_review` 等），同时加载会在插件装配期直接报错。切换必须原子操作：先移出旧包，再装 0.6.11，然后重载插件并刷新页面。

**数据仍然兼容，不需要迁移也能打开。** 沿用 `~/StoryDesk/projects/<id>/` 这套目录：

- 旧的 `.md` 章节（带 frontmatter）继续可读，写回时仍写回原来的格式，未知的 frontmatter 字段原样保留；
- 旧的审阅、提案、注意力记录都能读；旧版本遗留的提案默认不显示，也不重写、不误删；
- 新写入的正文是纯文本 `.txt` + 同名 `.meta.json` 元数据。

**如果想要统一格式**，可以运行迁移脚本把旧 `.md` 转成 `.txt` + 元数据：默认只打印计划（`--dry-run`），写盘要显式 `--apply`，写前会整本备份；逐章比对 sha256，只有与源文件逐字一致才删 `.md`，并留一份迁移报告供 `--verify` 复核。**注意：迁移后 0.5 插件只认 `.md`，会显示 0 章**——所以务必等旧插件已经移除、0.6 接管之后再迁移。

**这是重写，不是 0.5 的功能超集。** 0.5 的 19 页签流水线不再保留；0.5.2 是一条未发布的分支，上面开发中的部分能力没有进入这一版（相关开发记录已归档，不随仓库发布）。

## 六、已知限制

- 从「在默认浏览器打开」到「工作台加载完成」这条链路，桌面端需要你亲手确认一次（自动化测试只覆盖了链接拼接与降级提示）；
- 正文是纯文本：不做 Markdown 正文渲染，也不做富文本编辑；
- 阅读位置精确到段落（段首对齐），不追到行号；
- 冷读打分是「一次一章」提交，这是为了 JSON 稳定性的有意取舍——多章塞进一次调用容易解析失败、整轮作废；
- 旧项目的批量迁移是可选项，需要手动执行；
- 0.5.2 未发布分支上的部分能力没有进入本版，见上一节。

## 七、安装与升级

```sh
# 从 npm 安装（推荐）
dsh plugin --profile <你的 profile> add dsh-long-novel-workbench@0.6.11
```

也可以在 DSH 的插件管理里安装 / 更新 `dsh-long-novel-workbench` 到 `0.6.11`，或者用本地包目录安装。

升级时请按顺序：**移出 0.5 旧包 → 安装 0.6.11 → 重载插件 → 刷新 DSH 页面**。装好后侧栏底部会出现「📖 小说工作台」入口。

建议升级前先备份 `~/StoryDesk`（数据格式兼容，但备份永远不亏）。
