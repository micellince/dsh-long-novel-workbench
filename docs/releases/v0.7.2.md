# v0.7.2 · 长篇中文小说工作台

**发布日期**：2026-10-27
**npm**：`dsh-long-novel-workbench@0.7.2`
**GitHub**：<https://github.com/micellince/dsh-long-novel-workbench/releases/tag/v0.7.2>

0.7.1 把「审阅」重做成「问题单 + 修改稿」；0.7.2 补的是同一件事的另一半——**作者自己的意见**也进同一张问题单，而且 AI 动手改之前先问作者要什么。

- 问题页能直接「＋ 作者提问题」；想不出一条条问题，就用「💭 宏观提议」把想法丢进去，AI 陪你聊，聊定后交稿；
- 全文动作开工前先问「本次要求」，改写 / 扩写必须两次确认才覆盖正文（覆盖前自动备份）；
- 单章重写不再借用全文动作，改走问题页的「整章改写稿」，采纳后才覆盖原文。

**数据结构不变**（`novel.db` schema 仍是 v8），0.7.1 的作品直接升级可用。

---

## 一、作者自己的问题

0.7.1 的问题单里只有 AI 审出来的问题；作者想提意见只有正文批注一条路，而且没有地方写「我到底想改什么」。

0.7.2 把作者入口接进同一张问题单：

- **＋ 作者提问题**：四类问题（AI 化 / 逻辑与事实 / 文风漂移 / 其他）+ 范围（单章 / 跨章 / 全局）+ 可选段号或逐字引文 + 一句话说明；写了「我的要求」就直接生成出稿工作单，AI 按你的要求出稿。
- **💭 宏观提议（想到哪说哪）**：写不成一条条问题时，直接把想法丢进去——先讨论、再动手；问题卡上可以「💬 继续聊」多轮补充，聊定后由 AI 交稿（不改正文、不新增无关问题）。
- 作者问题与 AI 发现进同一张问题单，来源只做标签；筛选、批量出稿、采纳 / 继续改 / 忽略都一样。

## 二、全文动作：动手前先问要求

以前的全文动作只能选类型和范围，AI 不知道作者这一轮到底想要什么；改写 / 扩写还会直接改正文，心里没底。

0.7.2 改成：

- 开工对话框新增 **「本次要求 / 我的意见」**，随工作单发给 AI，并在提示词里列为最高优先级；要求可保存，开工后还能补发。
- **改写 / 扩写必须两次确认**才开工；覆盖前系统自动逐章备份，可从章节「历史版本」找回。
- run 绑定本书对话；暂停 / 中止改为「标记…（不停止对话）」；创建时阶段全部 pending、开工才 running。
- **单章重写改走问题页「整章改写稿」**：先入问题单、生成整章稿，采纳后才覆盖正文；服务端 run 不再接受单章 rewrite。

## 三、这一版不改什么

- 数据结构不变：`novel.db` schema 仍是 v8，0.7.1 的作品直接可用。
- 工具仍是 7 个；阅读 / 批注 / 编辑、账本、世界地图、导出、写作预设都没有动。
- 提案页只剩账本同步的 `ledger-fix` 批准在用（待并入账本页后删除）。

## 四、升级

```sh
# 从 npm 安装（推荐）
dsh plugin --profile <你的 profile> add dsh-long-novel-workbench@0.7.2
```

也可以在 DSH 的插件管理里把 `dsh-long-novel-workbench` 升到 `0.7.2`，然后**重载插件 + 刷新页面**。

## 五、已知限制

- 旧审阅 / 注意力 / 冷读的提示词函数仍留在 `lib/prompts.js`（对应工具已不注册、界面也不可达），后续清理。
- 按项目当前规则，本版**未运行自动化测试**（`test/` 仍是 0.6 行为断言），发布验收以作者手测为准。
