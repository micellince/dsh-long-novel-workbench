# v0.4.0 · 长篇中文小说工作台

**发布日期**：2026-10-22
**npm**：`dsh-long-novel-workbench@0.4.0`
**GitHub**：<https://github.com/micellince/dsh-long-novel-workbench/releases/tag/v0.4.0>

这一版把「能用」补成了「顺手用」：人物关系图、时间线泳道、章节自动保存与历史回滚、批量审稿/采纳、事实时间维度、Markdown 导入、EPUB/DOCX 导出、多预设对齐，并且第一次把测试和 CI 补齐。**数据格式向后兼容**：v0.3.x 的 `~/StoryDesk` 可以直接被 v0.4.0 打开。

---

## 一、新增功能

### 1. 人物关系图

人物页新增「列表 / 关系图」切换。关系图用 SVG 力导向布局（确定性初始化 + 80 次迭代），按角色着色（主角 / 反派 / 配角 / 龙套）；支持四种关系写法：`名字(关系)`、`名字（关系）`、`名字:关系`、`名字：关系`。关系目标还没建卡时显示虚线幽灵节点，点击可直接新建；节点可拖拽，悬停高亮相邻节点和边，点击打开人物编辑卡。

### 2. 时间线泳道图

时间线页新增「列表 / 泳道」切换。按卷分泳道（事件有 `volume` 时），否则每 20 章一条；横轴为章号，事件按重要度着色（一般 / 关键 / 高潮），点击编辑。伏笔的「埋设章 → 回收章」用贝塞尔弧线连接：未回收实线、已回收灰色虚线，跨泳道也画。顶部提供 0.5x–3x 缩放。

### 3. 自动保存 + 章节历史 / 恢复 / diff

- 章节编辑器停止输入 5 秒后自动保存，显示「未保存… / 保存中… / 已自动保存 HH:mm」；
- 关闭时若有未保存改动会提示；
- 每次覆盖且内容确实变化前，旧稿自动备份到 `projects/<id>/.backups/`，每章最多保留最近 100 份；
- 「历史版本」可列出备份、查看与当前稿的逐行 diff、恢复指定版本（恢复前会把当前正文再备份一份）；
- 手动保存、采纳正文提案、恢复历史版本统一走同一套备份函数，不再出现重复/漏备份。

### 4. 批量审稿 / 批量采纳

- 提案页：按类型筛选、单选 / 全选、批量采纳、批量驳回；单条失败不影响其他条，失败项逐条提示；
- 审稿页：按严重度筛选、全选、批量「标记已修 / 忽略」；
- 后端逐条执行并返回 `{accepted, failed}` / `{updated, missing}`，前端把失败项列出来。

### 5. 事实账本时间维度

事实新增可选字段 `validFrom` / `validTo`（生效章 / 失效章）。同一 `主体 + 属性` 只有两个取值的**生效区间重叠**且值不同才报冲突；不填表示从第 1 章起 / 一直有效。这修掉了「同一属性在不同阶段合法变化被一刀切报错」的老问题。表单与列表同步支持（`第 3 章起` / `第 3–10 章` / `全程`）。

### 6. Markdown 导入

作品库页新增「导入 Markdown」：输入本机目录路径 → 扫描预览（文件数、章节数、总字数、前 20 章标题）→ 填写作品名 → 导入为新作品。递归扫描（最大深度 5，跳过隐藏目录、`node_modules`、`.git`），优先按 `#` / `##` 标题切章，没有标题则一个文件一章；只读扫描，不改原目录。后端也支持 append 到已有作品并从现有最大章号续号（当前 UI 只暴露新建）。

### 7. EPUB 3 / DOCX 导出

除 Markdown 合集外，新增 EPUB 3 与 DOCX。实现零依赖：自带 ZIP 打包（`node:zlib` 的 `deflateRawSync` + 自实现 CRC32），EPUB 的 `mimetype` 作为第一条且不压缩，DOCX 章节标题使用 `Heading1`。前端直接下载。

### 8. 多预设 / 多卷对齐

作品新增 `activePresetId`，预设页可「设为当前」，对齐页显示当前预设名。预设支持可选的 `chapterFrom` / `chapterTo` 做分卷：命中当前预设时用该预设，否则按分卷汇总计划章数与字数，最后回退到第一个预设（保持旧行为）。

### 9. 测试、CI 与工程文档

- `test/`：32 个 `node:test` 用例，零依赖，全部用临时 `STORY_DESK_ROOT`，覆盖事实区间冲突、伏笔超期、未建卡人物、章节备份/历史/恢复、提案单条与批量、对齐、导入、ZIP/EPUB/DOCX 结构；
- `.github/workflows/ci.yml`：Node 22 / 24 矩阵，跑 `npm test` + `node --check index.js` + `node --check client.js`；
- `.github/workflows/publish.yml`：push `v*` tag 时校验版本一致性并发布 npm（需配置 `NPM_TOKEN`）；
- 新增 `CHANGELOG.md`、`CONTRIBUTING.md`、Issue 表单、PR 模板；README 更新功能列表、源码安装、开发测试说明。

## 二、修复

- **插件在某些宿主里客户端不加载**：`package.json` 的 `exports` 缺少 `"./package.json"`，宿主解析 `dsh.client` 时会失败（桌面端老版本可能容忍，CLI/Web profile 会直接跳过客户端）。v0.4.0 补上该导出。
- **时间线泳道在章节少时卡片重叠**：步长改为至少一张卡片宽；顶部留出伏笔弧线空间，跨章弧线不再被裁掉。
- **同一属性不同阶段合法变化被判冲突**：改为生效区间重叠才报。
- **README 声称「内置演示作品」但代码里没有**：删除该描述，改为引导新建或导入。
- **历史版本 diff 混入 frontmatter**：前端 diff 前剥离 YAML frontmatter，只比较正文。

## 四、验证与兼容

- `npm test`：32 个真实用例全绿（`node --test` 自动发现显示 33，多出的是空的 helpers 文件）；

## 五、已知问题 / 下一版

- **i18n 未做**：UI 文案仍是中文硬编码，插件行元数据已中英双语；
- **性能**：`getBundle` 仍全量读取章节，几百章后需要分页/懒加载 + 列表虚拟化；
- **导入增强**：append 模式已有后端无 UI；frontmatter 映射、AI 生成摘要/人物/事实还没做；
- **章节版本**：历史分页、跨版本对比、手动命名版本还没做；
- **测试**：真实 RPC 冒烟需要 `index.js` 导出 `handleRpc` 或注入假 ctx，当前用源码断言 + lib 直测；
- 历史版本的 `chapter.version` 返回完整文件（含 frontmatter），前端已剥离；第三方调用方需注意。

## 六、升级方式

```sh
# npm 安装（发布后）
dsh plugin --profile <你的 profile> add dsh-long-novel-workbench

# 或从源码
git clone https://github.com/micellince/dsh-long-novel-workbench.git
# 在 DSH 插件管理里 install_bundle 指向本地目录
```

升级后：重载插件 → 刷新页面 → 打开工作台。建议先备份 `~/StoryDesk`（虽然数据格式兼容，但备份永远不亏）。
