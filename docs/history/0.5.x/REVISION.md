# 全文改动（Revision）

> 状态：**契约层 + 执行链路已实现**（`lib/revision.js`、`revision.json` 单例、`revision.*` RPC、`novel_desk_revision` 工具、UI 面板），L1/L2/L3 可跑，L4 拒绝。
>
> **位置**：`📚 整本书` 页的子模块之一（与「生成整本书 / 扩写 / 审阅」并列），不是独立页签。

## 一句话

扩写是「有 → 更厚」，改动是「有 → 换皮」。**换皮有四种皮，危险程度差三个量级。**

## 为什么文风改动简单、价值观改动很难

文风改动的不变量是**情节**：每章独立重写一遍，只要事件、人物动作、对白信息量、专名、数字、章末钩子不变，章与章之间就**没有依赖**。可以并行、可以批量、可以全自动。

价值观改动的不变量只剩**世界设定**。它动的是人物的立场与动机，而立场是**全局量**：

- 第 10 章把「复仇到底」改成「放下仇恨」，第 30 章的「他攥着刀站了一夜」就不再成立；
- 叙述者的价值判断散落在每一段的措辞里，逐章独立改会在第 12 章和第 40 章之间产生自相矛盾的语调；
- 人物动机一变，读者的预期变了，**钩子与回报的有效性**也跟着变。

所以价值观改动不能按「章」为单位，只能按「设定 → 级联」为单位。这是分层存在的唯一理由。

## 四层契约

| 层 | 名称 | 可动 | 冻结 | 依赖 | 自动化 | 风险 |
|---|---|---|---|---|---|---|
| **L1** | 语域层（文风） | 句式、用词、比喻、描写顺序、情绪表达方式 | 事件、动作结果、对白信息量、专名、数字、章末钩子、事实账本 | 逐章独立 | 可整批自动 | low |
| **L2** | 侧写层（场景/对白） | 场景增减、对白措辞、配角戏份 | 事件与结果、因果链、关系变化、钩子 | 逐章轻依赖 | 批末审一次 | medium |
| **L3** | 语义层（价值观/动机/主题） | 人物立场、叙述者判断、主题走向 | 世界设定、时代地理门派规则 | **全局先行** | 逐章确认（默认） | high |
| **L4** | 结构层（情节/结局） | 事件本身、人物生死、结局 | 世界规则 | 大纲 | 大纲闸门 | critical |

**L4 不由本引擎承接**——它已经是重写，走扩写/大纲流程。`validateRevisionContract` 会直接拒绝。

## 可以多选，而且通常该多选

改动不是"一次只能一层"。契约接受 `tiers: ['L1','L2']`（也接受 `'L1+L2'` 字符串），组合规则：

| 组合项 | 规则 |
|---|---|
| 可动 | 各层**并集**（L1+L2 = 既换语域，也可动场景细节） |
| 冻结 | 各层**交集** + 基线保护项（世界设定、时代/地理/门派规则） |
| 风险 | 取**最高**（L1+ L2 → medium） |
| 自动化 | 取**最严**（含 L2 就不再整批并行，改为批末审） |
| 依赖 | 含 L3 → **全局先行**（先设定层、再逐章级联），否则逐章 |
| 作者确认 | 取**最严**（含 L3 → 默认逐章停，可在契约里选别的停顿方式） |

典型选择：

- **只改文风 / 清 Markdown / 调句式** → **L1**（Markdown 清理不属于任何一层，它是所有改动的硬性前置，`apply` 时强制 `md.total === 0`）
- **文风 + 顺带补场景细节、改对白措辞** → **L1+L2**
- **改价值观** → 必须含 **L3**，且必须写价值变更书；可以与 L1/L2 同时选。默认逐章停，也可以选「每批停 / 出问题才停 / 一路跑到底」

## 目标的来源

三种，可组合：

| `goalMode` | 含义 |
|---|---|
| `preset` | 目标来自预设（`presetId` 指向预设；不写 goal 也行，系统会用预设 tone/规则生成一句可判定目标） |
| `custom` | 目标自己填（必填） |
| `both` | 两者都要：预设给文风规格，作者给补充目标；冲突时以作者目标为准 |

工作单里预设的 tone / structure / styleRules / styleCards 会作为独立一节注入，与「本次目标」并列。

## L3 的执行顺序（硬性）

1. **价值变更书**（charter）——必填三项，缺一即拒：`oldValue`（现在的立场）、`newValue`（要改成什么）、`affectedCharacters`（牵连哪些人）。

2. **影响面分析**（`impactMap`）——按人物名/关键词扫全部章节，输出受牵连章清单。它不判断对错，只负责「别漏章」。漏一章的代价是全书出现两个立场。

3. **先改设定层，再级联正文**——批次 0 永远是 `kind: 'settings'`（人物卡、预设立场、主题陈述）；之后按作者选的批次大小切正文批（默认逐章，可选每 5/10 章或整本一批），是否逐批停下由停顿方式决定。

## 批次大小与停顿方式（L1/L2/L3 通用，在「开始」这一步选）

这两个参数是**执行设置**，不是方案的一部分：UI 上它们放在「④ 执行」卡片里，作者选好再点「开始」；后端在 `revision.start` 收到 `batchSize` / `stopMode` 后**先重排批次再投递工作单**。重排按章保留进度——已经 `done` 的章在新批次里仍是 `done`，`needs-fix` 仍是 `needs-fix`，不会因为换批次大小丢掉已改好的章。`revision.plan` 也能带这两个字段，只作为方案里的默认值。

批次大小只决定**检查点密度**，不改变工作量：每章仍是一次独立改写，「一次全改 52 章」= **1 个批次依次跑 52 章**，不是一个模型调用写 52 章。

| 批次大小 | 含义 |
| --- | --- |
| 每 5 章 / 每 10 章（默认 5） | 按章数切批，每批是「一批检查点」 |
| 一次一章（`batchSize: 1`） | 逐章一批，最细的检查点 |
| 一次全改（`batchSize: 'all'`） | 全书 1 批，跑到底再汇报 |
| 自动（不指定） | 不传 batchSize：L3 逐章，L1/L2 每 5 章 |

停顿方式（`stopMode`，L1/L2/L3 通用；L3 只是多一个「设定层批 0 在最前」的顺序约束）：

| stopMode | 行为 |
| --- | --- |
| `per-batch`（默认） | 每批结束停下等作者；L1 单层时只有第一批（样张）停 |
| `fix-only` | 一直跑；同章两次修不过闸门、或撞冻结项才停 |
| `run-to-end` | 不停，全部改完再汇报；预算到顶自动暂停 |

任何模式下每章仍过**保真 + Markdown 残留**两道闸门，单章不过关标 `needs-fix`，不会静默放过。

## 两道闸门

- **保真闸门**：改前从原章抽锚点（事件、专名、数字、章末钩子），改后必须全命中。不命中打回重改，超次转人工。
- **风格闸门**：按预设 `styleCards` 算指标（`lib/aistyle.js`），未进区间即不合格。

L1 是唯一同时过两道闸门就能全自动跑的层；L2 加连续性检查；L3 额外要**立场一致性检查**（每个角色在每章的立场必须同向）。

## 与其它模块的关系

- **扩写**：L4 走那边；L1–L3 不走扩写（扩写明令「风格/POV 不漂移」）。
- **预设**：L1 的目标来自预设的 `styleCards` 与 `anchors`；L3 的目标来自价值变更书。
- **去 AI 化审稿人**：L1 最常见的触发源；它输出偏差表，改动引擎按表逐章修。
- **章节历史**：每批改动前自动备份，回滚走 `listChapterHistory` / `restoreChapterVersion`。
