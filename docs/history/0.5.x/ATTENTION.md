# ATTENTION · 注意力模块设计（v0.6 草案）

> 一句话：**一本书好不好，先看它抓不抓人。** 连续性、文笔、逻辑自洽是"不扣分"，注意力是"能不能让人读下去"。
> 本文件是 P0 开发前的契约：数据、导航、打分、prompt、检查、验收。确认后照此实现。

---

## 0. 一号原则

**ATTENTION IS ALL YOU NEED。** 怎么吸引读者怎么来，一切为读者服务。先抓人，再自洽：每章必须有核心注意力；事实自洽是底线，不是目标。

这条原则已经落到三处：
1. **界面**：工作台常驻原则条（所有页签可见）；总览页置顶 hero（口号 + 平均注意力/最低三章/未标章数）；注意力页与分工页各加原则行；分工页注明「注意力设计师权重最高（10）：每章先出注意力设计，再谈情节」。
2. **生成工作单**：`novel_desk_context` / `novel_desk_plan` / 常规交接 prompt 首行注入创作第一原则；plan 工作单把「第一优先级：注意力」排在大纲/事实/时间线/伏笔/冲突/地点之前，含最近 6 章曲线、疲劳预警、目标分区间、四拍要求；**强制补强**：上一章 `designScore-score ≥ 20` 或 `score < 全书均值-10` 时点名最弱一环，要求本章补上。
3. **硬约束**：`createProposal(kind=plan)` 必须带 `data.attention`（type/hook/tension/payoff/cliff/designScore），否则直接报错；章节提案采纳时合并 `data.attention`，没有设计时返回 `attentionWarning`。零上下文冷读（fresh-read）不注入原则，保持读者视角纯净。

## 1. 定位

注意力是**父级模块**，伏笔、冲突、高光是它的三个**素材子项**：

| 子项 | 在注意力里的角色 |
|---|---|
| 🧩 伏笔 | 悬念/期待：答应读者"以后有事"，是延迟兑现的钩子 |
| ⚔️ 冲突 | 张力引擎：让读者担心主角失去什么，是承压来源 |
| ✨ 高光 | 兑现证据：这一章真的写出了好段落，是回报 |
| ⚡ 注意力 | 把三者组织成每章的钩子 → 张力 → 回报 → 牵引，并给出**一个总分** |

原则：
1. **每章必须有核心注意力**，且只能有一个主类型；
2. **打分只给一个总分（0–100）**，说明可以写详细（四拍体检、最弱一环、弃读点、下一章意愿）；
3. 注意力是设计（写之前定）也是实测（写之后读）；两者差值是最值钱的诊断信号；
4. 不为了"好看"而堆辞藻——注意力才是验收标准。

## 2. 侧边栏（按类型分组，注意力组置顶）

现有页签**一个都不删**，只重排 + 加分组标题。逻辑：**读者体验 → 正文 → 设定 → 验收 → 工具**。

```
总览
├─ 注意力 ──────────────  ← 组标题
│  ⚡ 注意力
│  🧩 伏笔
│  ⚔️ 冲突
│  ✨ 高光
├─ 正文 ────────────────
│  📄 章节（含大纲）
│  👤 人物
│  🕰️ 时间线
│  ⚖️ 事实账本
├─ 验收 ────────────────
│  📝 审稿
│  📥 提案
│  🎯 对齐
└─ 工具 ────────────────
   📈 仪表盘
   🤖 分工
   🎛️ 预设
   ⚙️ 设置
```

- 组标题是导航里的细分隔行（不可点击），统一 `.sd-nav-group`。
- 总览保持第一位（它是首页），注意力组紧随其后——这是"最上面"。
- 伏笔/冲突/高光保留原页签与原有编辑、加入清单入口，不搬数据、不降级功能。

## 3. 数据契约：`attention.json`

每章一条；`KIND_FILES` 新增 `attention: 'attention.json'`，进 bundle、进 `getEntities/upsertEntity/deleteEntity`。

```jsonc
{
  "id": "att-0003",
  "chapter": 3,
  "type": "emotion",            // event | emotion | language | mystery | relationship
  "score": 72,                  // 唯一总分，0-100（冷读实测；没读过就留空）
  "designScore": 80,            // 设计师目标分，0-100
  "verdict": "犹豫",             // 会 / 犹豫 / 不会 读下一章
  "weakest": "cliff",           // hook | tension | payoff | cliff（诊断用，不打分）
  "dropRisk": "第 9 段：回忆插叙约 600 字，与当下无关",
  "hook": "开篇 3 行内抛出的问题/画面",
  "tension": "本章承压点：主角失去/被逼什么",
  "payoff": "本章兑现了什么（爽点/揭示/情绪释放）",
  "cliff": "章末留下的未决问题",
  "question": "读到这里，读者最想知道的一句话",
  "emotion": "（可选）本章主情绪 / 情绪走向",
  "detail": "详细说明：四拍逐条给依据、引用原文；最弱一环；弃读点；下一章意愿。长度不限。",
  "status": "planned | drafted | verified",
  "note": ""
}
```

**字段归属（同一条记录，两个人各写一半，按 `chapter` 合并）**

| 谁写 | 字段 | 时机 |
|---|---|---|
| 注意力设计师 | `type` `hook` `tension` `payoff` `cliff` `question` `designScore` `status` | 生成大纲 / 下一章方案 / 正文时先产出；已有书用清单任务补 |
| 独立审稿人（冷读） | `score` `verdict` `weakest` `dropRisk` `detail` | 正文写完后实测 |

合并规则：同一章只有一条；谁后采纳都只覆盖自己给的字段；空值不擦除对方字段；plan 提案里的 `data.attention` 采纳后也会补进账本。

**三个子项零迁移**：不改 `foreshadow.json` / `conflicts.json` / `highlights.json` 的结构，注意力页按章号自动聚合：

- 本章埋的伏笔：`foreshadow.setupChapter === chapter`
- 本章收的伏笔：`foreshadow.payoffChapter === chapter`
- 本章引爆的冲突：`conflicts.resolveChapter === chapter`（P1 再加 `escalateChapters: []` 支持"本章升级"）
- 本章高光：`highlights.chapter === chapter`

老作品打开时 `attention.json` 自动建空；第 11 个角色自动补入（同 agent-10 的迁移逻辑）。

## 4. 打分口径（100 分制）

| 分段 | 含义 |
|---|---|
| 0–39 | 读不下去：钩子缺失或中段失压，会弃读 |
| 40–59 | 能读但平淡：没有明显错误，但没有追更动力 |
| 60–79 | 合格想追：有钩子有回报，愿意点下一章 |
| 80–100 | 强吸引：会立刻点下一章，甚至会回头重读 |

必填三件事：**最弱一环、一个弃读点（位置+原因）、会不会读下一章（会/犹豫/不会）**。禁止轻易给 80+；给高分必须引用原文证明。

**按类型校准**（`genreProfiles`，P0 先内置武侠/推理/科幻/言情/文学/悬疑六套，每套 5–8 条读者预期）：

- 武侠：爽感兑现、门派悬念、情义张力、武打画面、江湖规则
- 推理：谜面吸引力、线索公平、嫌疑人动机、反转合理性
- 科幻：概念震撼、设定自洽、推演逻辑、尺度感
- 言情：关系张力、情绪投射、误会与和解的节奏
- 文学：语言质感、情绪暗流、细节密度、余味
- 悬疑：信息差、压迫感、真相饥饿度

**诊断模板**（`detail` 字段的推荐格式）：

```
总分 62/100（情感型）
钩子：第 3 段"她把手缩回去"有效，但出现太晚（第 900 字）
张力：第 7–11 段日常对话稀释压力，无承压
回报：第 14 段身份暗示兑现了一半
牵引：章末停在情绪上，没有未决问题 ← 最弱一环
弃读点：第 9 段回忆插叙约 600 字，与当下无关
下一章意愿：犹豫
```

## 5. 独立审稿人（第 10 角色）：只负责"实测打分"

仍是零上下文，但**不写设计字段**（四拍/type 归设计师）。prompt 追加（单章）：

```
本作类型：武侠。该类型读者预期（打分校准）：1) 爽感兑现 2) 门派与师承的悬念 3) 情义与背叛的张力 4) 武打画面 5) 江湖规矩与代价。
除首读意见外，给这一章一个 0-100 的注意力总分（按该类型读者预期校准），并写一段详细说明：
钩子/张力/回报/章末牵引哪里有效、哪里不足、最弱一环、一个弃读点（段落位置）、会不会读下一章（会/犹豫/不会）。
用 novel_desk_propose(kind=attention) 提交本章实测记录（chapter/score/verdict/weakest/dropRisk/detail）；
钩子/张力/回报/章末牵引的设计归注意力设计师，不要写这些字段（type 也不要写），不要改正文。
```

全书模式：沿用现有分批工作单，每个子 Agent 除首读意见外**返回该批每章 0–100 分 + 一句理由**；主会话汇总成一条 attention 提案（全章实测 items）+ 整条曲线 + 最低五章。

## 6. 第 11 角色：注意力设计师（weight = 10，最高）

- **职责**：为每章设计注意力结构并调度素材——本章主类型；在哪拍埋哪条伏笔、计划第几章收；哪条冲突在本章升级/引爆；保留哪段高光作为兑现；给出目标分 `designScore`；保证同类型不连续超 3 章。
- **输入**：大纲 + 最近 attention 记录 + 冷读实测分 + 伏笔/冲突/高光账本。
- **输出**：`attention` 提案（每章一条，含 hook/tension/payoff/cliff/question/designScore）+ 「下一章注意力设计」写入下一章工作单 + plan 提案里的 `data.attention`。
- **在哪跑**：
  - 新书/连载：写大纲（`enrich-outlines`）、做下一章方案（`novel_desk_plan` / `next-chapter-plan`）、写正文（`continue-chapter`）时**先产设计**；
  - 已有书：注意力页 / 总览卡的「＋ 加入清单：AI 补齐注意力机制」（`task=attention-design`），AI 逐章读正文 + 大纲 + 伏笔/冲突/高光，补 design 字段（书大时分批）；
  - 导入后审阅（`import-review`）顺手补设计。
- **权重**：`weight: 10`（总编 9、独立审稿人 8、其余默认 3）。用途：派单顺序、汇总排序、工作单优先级提示；**不改变"提案必须作者采纳"**。
- **分工表**：新增「权重」列，按权重降序展示；`order` 仍追加为 11，不重排既有角色。

## 7. 工作流闭环

```
注意力设计师：定四拍 + 目标分（写大纲/下一章/正文时先产出；老书用清单补齐）
        ↓ 作者采纳（attention 记录，design 字段）
写正文（按设计落笔）
        ↓
独立审稿人冷读：只写实测（score/verdict/weakest/dropRisk/detail）
        ↓
对比 designScore 与 score：差 ≥20 → 设计没兑现 → 进修订单
        ↓
作者验收 → attention 曲线更新 → 下一章继续（防同类型疲劳）
```

## 8. 确定性检查（不花 token）

| 规则 | 级别 |
|---|---|
| 已写章节缺 attention 记录 | warn |
| 已写章节 `cliff` 为空 | warn |
| 同一类型连续 > 3 章 | warn |
| 相邻章分数下降 ≥ 15 | warn |
| `designScore` 与 `score` 差 ≥ 20 | warn |
| 开篇前 3 章没有事件/悬念型 | warn |
| 全书平均分 < 60 | error |
| 冷读跑过但没回填 score | info |

老章节的 attention 记录为空时，`measuredScore` 缺失不报错，只在注意力页提示"N 章未标"。

## 9. 界面

**⚡ 注意力页**
1. 顶部统计：全书平均分、最低五章、未标章数、疲劳预警条数；
2. 曲线：X 轴章号、Y 轴 0–100、颜色=类型、红点=弃读点、虚线=designScore；点一章展开；
3. 章节诊断卡：总分、类型、verdict、四拍文本、最弱一环、弃读点、详细说明；
4. 卡底三个折叠区：本章伏笔（埋/收）、本章冲突、本章高光——点击跳原页签编辑；
5. 「AI 冷读本章」按钮：加入清单 → 独立审稿人任务。

**总览首屏**：注意力卡（平均分、最低三章、疲劳预警、未标章数），排在今日进度之前。

**分工页**：新增「权重」列；注意力设计师行高亮（同独立审稿人卡的做法）。

## 11. 未决/风险

- 注意力分数的"宽容度"：prompt 禁止轻易 80+，但仍可能偏高——用 designScore 对照与历史分布校准；
- 每章都标 attention 对 133 章的《鱼龙舞》是成本项：冷读全书必然走分批，P1 再做；
- 100 分制的相邻章波动需要观察：若噪声大，改为 5 分档映射（0/20/40/60/80/100）。
